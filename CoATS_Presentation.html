The challenge
The Problem We Solve

Current complaint tracking in law enforcement departments suffers from critical systemic failures.

📋
Paper-Based Chaos
Complaints registered in physical registers, FIR books, and loose sheets. Files misplaced, damaged, or inaccessible across branches.
"Which file is the Sharma complaint in? It was here last week…"
🔍
Zero Accountability Trail
No timestamp-verified record of who updated a case, who viewed it, or when. Supervisors have no real-time view of case stages across branches.
"Was this case updated before or after the court date? We can't prove it."
🏢
Branch Silos
Each police station operates in isolation. Cross-branch cases require phone calls, physical transfers, and manual coordination — all error-prone.
"The accused was seen at three stations. No one knows the full picture."
🔒
Weak Security
Shared credentials, no login audits, no location tracking. Sensitive complainant data exposed. No way to detect unauthorized access or tampering.
"Anyone with the password can change a case record. There's no log."
The solution
What CoATS Delivers
📁
Smart Case Management
Register complaints with crime number, section of law, accused details, and gist. Track through stages: Registered → Under Investigation → Charge-Sheeted → Closed. Full file attachment support.
🔐
Military-Grade Auth
Password + TOTP (Google Authenticator) or Passkey (Face ID, fingerprint). Every login logs IP address, location, and timestamp. Tokens expire in 15 minutes. Refresh tokens for seamless sessions.
⛓
Blockchain Integrity
Hyperledger Fabric smart contracts anchor every case creation, stage change, and progress update to an immutable ledger. SHA-256 fingerprints — no PII stored on-chain.
📊
Analytics Dashboard
Visual charts showing case distribution by stage and branch. Supervisors see the full department picture. Officers see their assigned cases. Real-time stats: open, pending, closed counts.
👥
Role-Based Access
Case Holders see only their branch's cases. Supervisory roles get cross-branch visibility. HQ oversight over all stations. Granular access control — nobody sees what they shouldn't.
📝
Progress & Actions
Log dated progress entries with next-action reminders. Create and complete action items. Attach documents, FIR copies, evidence files — all stored in Cloudflare R2 with signed download URLs.

System Architecture
Zero-trust security
Security Architecture
🔑 WebAuthn / Passkeys
FIDO2-compliant passwordless login using device biometrics — Face ID, fingerprint, or hardware key. Credentials never leave the device. Phishing-proof by design.
  • Supports singleDevice & multiDevice credentials
  • Challenge-response — no replay attacks
  • Public key stored server-side only
  • Device type & transport logged
📱 TOTP 2FA
Time-based one-time passwords via Google Authenticator or any RFC 6238 app. Secret stored AES-256-GCM encrypted. Brute-force protected with lockout.
  • AES-256-GCM encrypted TOTP secrets
  • Backup codes as bcrypt hashes
  • Failed attempt counter + lockout timer
  • 5-minute pending token for 2FA flow
🗝 JWT Token Architecture
Short-lived 15-minute access tokens prevent session hijacking. 7-day refresh tokens on HttpOnly cookies only. Access tokens carry full role & branch context.
  • Access token: 15 min, HS256 signed
  • Refresh token: 7 days, httpOnly cookie
  • 2FA pending token: 5 min only
  • Automatic token refresh on expiry
📍 Audit & Location Trail
Every login event records IP address, GPS coordinates, location name, and timestamp. Every security action is immutably logged. Complete accountability chain.
  • Login IP + geolocation stored per user
  • Audit log: action, detail, IP, timestamp
  • Indexed for fast forensic queries
  • Rate limiting on all auth endpoints

Smart Indexing
Composite indexes on stageId, assignedOfficerId, branchId, isActive. Audit log indexed on userId, action, and createdAt for fast forensic queries.
Unique Constraints
Case UID globally unique. crimeNumber unique per branch. Credential IDs unique per passkey. No duplicate records possible at the database level.
Cascade Integrity
CaseFiles, CaseActions, and CaseProgress all cascade-delete with their parent Case. Data stays clean when cases are archived or removed.
Blockchain TX IDs
Every Case, CaseProgress, and CaseAction row stores its Hyperledger Fabric transaction ID for cross-verification between the database and the immutable ledger.
Immutable trust
Hyperledger Fabric Integration
1
Case Created
Officer registers a complaint. recordCaseCreated() smart contract called with SHA-256 fingerprint of caseUid + officerId + crimeNumber + timestamp.
TX: a1f3b2c...d09e4 | fingerprint: 5f3a8b...
2
Stage Transitions Anchored
Every time a case moves stages (Registered → Investigation → Charge Sheet), recordStageChange() logs old stage, new stage, officer, and timestamp.
3
Progress & Actions Logged
Each progress entry and completed action is anchored. Composite keys: PROGRESS\0{caseUid}\0{progressId}. Full query API available.
4
Non-Blocking Architecture
All Fabric calls are fire-and-forget — they never slow down the API response. TX IDs saved back to PostgreSQL asynchronously. App works perfectly with Fabric disabled.
Why this matters
Tamper-Proof Evidence
No database admin, no officer, no IT staff can alter a historical record without the blockchain detecting it. Every fingerprint can be re-verified independently.
PII Protection
Raw complainant data is NEVER stored on-chain. Only SHA-256 fingerprints. Blockchain verifies integrity without exposing sensitive information to the ledger.
Court-Admissible Trail
Cryptographic proof that a case existed, was updated, and was never tampered with. TX IDs link every database record to an immutable Fabric ledger entry.
Dual-Mode Deployment
File-based certs for local/on-prem deployment. Base64 env vars for cloud/serverless. Graceful degradation — system runs fully without Fabric configured.
